# 逐条调整头部点云与腕部图像中的位姿

本工具用于人工辅助定位、配准候选审阅和坐标对应。原始采集保持只读；调整记录另存，不自动变成训练真值。

当前界面已拆成两组同时显示的调节栏：左图下方“点云位置调节”，右图下方“像素匹配调节”。每组各有六个滑条和数值框；左右修改互不覆盖。原始点云保持固定，移动的是模型。右侧对象选择仍可在光模块／插座之间切换。

初始化和颜色后续更新：优先用右侧“四个结构角点＋双目深度”建立初值，再调滑条。点云上方可选“原始 RGB 彩色”“彩色＋选区高亮”“灰度”，并调整点大小、勾选“只看目标附近”。绿色／紫色点分别表示模块／插座的图像选区辅助色，不是自动分割结果；橙／青线框仍表示两个模型。

## 打开与恢复

当前窗口地址：`http://127.0.0.1:8876`。服务停止后，从仓库根目录运行：

```bash
OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 \
  /data/omi_runtime/envs/foundation_stereo/bin/python \
  scripts/perception/pose_review_server.py \
  --output /data/omi_runtime/runs/head_wrist_pose_review_20261122 \
  --port 8876
```

在浏览器打开上述地址。若普通浏览器WebGL空白，可使用独立软件渲染窗口：

```bash
google-chrome --new-window \
  --user-data-dir=/data/omi_runtime/runs/head_wrist_pose_review_20261122/chrome_profile \
  --use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader \
  http://127.0.0.1:8876
```

默认读11月22日备份的287组四图；也可用`--backup`指定同格式备份根。`--calibration`可指定另一份明确使用OpenCV fisheye格式的腕部内参JSON；不要随意更换已标注会话的标定或模型。沿用同一`--output`恢复人工结果，新实验使用新目录。源码依赖兄弟仓库`FoundationStereo/scripts/infer_pose_review_sample.py`、既有推理环境和模型权重。

## 操作顺序

1. 顶部选样本，右侧选择“光模块”或“插座”。可勾选“只看已有点云”。首条包含助手准备的演示候选，尚未人工验收。
2. 左侧切到“头部图像”，点“框选目标”，拖出目标矩形，避免绿色挂件、夹爪和桌面。尚无点云时点“为此条生成双目点云”，等待任务完成。
3. 优先点“在头部照片上选4个结构角点”，按示意图顺序点击，再点“4点＋深度初始化”。模块选金属顶面的插入端两角和尾部金属盖两角；插座选白色框架**顶面**外侧四角，不能把前侧底边当顶边。点错可退一个；四角不可见时不要猜。首条另有助手准备的“载入本条建议初值（待审阅）”，可撤销。旧的“ROI→多方向候选”收进折叠区，仍可能错面；下支架不参与拟合。
4. 直接使用左图下方“点云位置调节”的XYZ、Roll、Pitch、Yaw滑条或数值框修正模型在点云中的位姿。XYZ单位mm，角度单位°。每组独立的“粗调”扩大范围，“范围归中”以当前值重新设置范围；数值框可直接输入范围外的绝对值。右图的位姿不随左侧调整改变。
5. 使用右图下方“像素匹配调节”独立调整腕部投影，左侧点云位姿不变。没有初值时点对应组的“建立点云初值”或“建立腕部初值”。两组都有“恢复本次载入值”，只恢复该组；全局“撤销”可撤销最近一步。图像仍支持缩放、平移和隐藏线框。右组使用腕部相机光学坐标，不是机器人腕关节坐标，也不是直接用像素作为XYZ单位。
6. 需要像素精修时，点“添加对应”：先在当前模型线框上点一个顶点，再点原图中的对应结构位置。至少4个分散、不共线的对应后点“≥4点精修”。同一顶点重复选取会更新其位置。Esc退出，清空或撤销可恢复。不要选贴纸、绿色挂件、夹爪、未知遮挡边界或模型内看不见的顶点。
7. 同一对象在头部和腕部都有候选后，可点“用当前目标的两套位姿求外参候选”。生成或手动修改外参本身不会覆盖左右拟合；只有显式点击“应用外参到腕部（替换两目标投影）”才将两目标重新映射，且可撤销。高级外参滑条折叠在同一节中。另一个对象用于独立检查，不能把构造出的零误差当作标定成功。
8. Ctrl+S或点保存。上一条／下一条会先保存当前改动。关闭页面前保存；浏览器会提醒未保存修改。人工已审阅只是工作状态，不会打开训练标签有效标志。

点云交互：左键旋转、Shift＋拖动平移、滚轮缩放。两张图像与滑条使用原始1920×1080像素投影，显示缩放不改变标定。线框展示完整结构（包括遮挡部分），不是可见性或分割结果。

“聚焦目标”现在优先依据选区内实际点云，而不是跟随可能错误的模型初值。目标选区及邻域保留密集点，远处才抽稀；RGB由对应头部原图和本条IR→RGB外参投影，RGB视野以外用灰色。颜色切换和局部显示不改变点的位置。

“当前初值附近微调”不再重新搜索24种方向；只做有位移／旋转限制的局部拟合，尝试偏移过大时拒绝并保留初值。首条实际测试触发了这个保护，因此不要把该按钮当作保证改善的自动精配准。

## 输出

- `annotations/<sample_id>.json`：每对象`head`／`wrist`的4×4变换、选区、候选、结构点对应、外参候选、审阅状态、备注。
- `history/<sample_id>/`：每次保存的独立版本；版本冲突会拒绝覆盖。
- `initialization_proposals/<sample_id>.json`：预备的四点候选及输入来源，显式载入才生效；不是已确认标签。
- `clouds/<sample_id>/`：新生成的米制点云、输入哈希、报告、推理日志。旧五组点云直接读取原备份。
- `session.json`：数据来源、模型文件哈希、腕部标定文件及约定。

所有变换为`T_目标坐标系_from_来源坐标系`，矩阵平移用m；界面显示mm。Euler采用固定轴XYZ，对应`Rz(yaw) Ry(pitch) Rx(roll)`。

头部位姿使用`camera_infra1_optical_frame`；叠加到头部RGB时使用每条样本的工厂IR→RGB外参。腕部使用`omi_wrist_camera_optical`。每条独立存`T_wrist_from_head`，不默认整个数据集共享一个刚性相机关系。

模型固定为V4-r05几何（排除绿色挂件和假设内部阴影块）、SIM-r06插座固定外观件；不包含等效动态触点。外观、真实尺寸与接触精度需分别评价。腕部标定与新采集相机身份未确认，曝光同步未认证；手动拟合低残差不等于真实6D精度。
