# 副作用与证据边界

## 文件和输出

主 CLI 的 `smoke`、便携包默认配准入口、资产导出、场景生成及两引擎脚本都要求新的输出目录，遇到已有目录会拒绝。源包、冻结模型、原始点云和旧实验不做原地替换。

并非所有工具都有同样的保护：Blender 原生命令的渲染输出、包内模型检查脚本的报告路径可能覆盖同名文件。教程使用新目录；运行前核对 `--output`、`--report` 或 `--render-output` 的用途。

数据、权重、SDK、软件安装包、虚拟环境、缓存和输出放在外部资源根目录。忽略规则不能替代检查提交内容；历史清单中的绝对路径是证据，不应批量替换以掩盖来源。

## 环境与仿真

主环境不安装 GPU 框架。模型任务、MuJoCo、Blender 和 Isaac 使用各自解释器；Isaac 启动命令清除外部 Python／Conda 动态库路径。本轮不修改系统 GPU 驱动。

Isaac 测试只加载本地扩展并禁用扩展注册表下载；首次采用通用启动方式时曾因依赖下载超时，不能把该失败日志当作最终通过记录。当前通过证据在[引擎能力](agent/simulation/evolution/engine-scenes.md)。

## 验证等级

区分：资源已到达、静态／导入检查、自动测试、实际后台运行、GUI 人工观察、设备只读检查、真机运动。本机已有前四类中的相应证据；GUI、Isaac RTX 和真机操作未验收。

局部表面残差不是位姿真值误差；物体落台不是精细夹持／插接验收；MuJoCo 图像不证明 Isaac 已渲染；旧机的成功记录不证明本机已复跑。具体物理简化见[外观与碰撞分离决定](agent/simulation/decisions/001-visual-and-collision.md)。

## 外部系统

主项目没有 ROS、机械臂 SDK 或真机执行入口。阅读 `omi_proj` 的资料只用于资产定位，不能据此运行其控制脚本或连接设备。厂商资源留在本地，公开再分发需遵循其许可。
