# Isaac控制吞吐：原厂IK、CPU完整周期与快速采集总账

## 当前阶段收口（2026-11-24）

用户要求“暂时先这样”，并将当前进展记录到纪传体与编年体。本轮停在已验证的控制吞吐／采集优化状态；本次收口只更新记录，不再启动实验或训练。按阶段阅读见[本窗口编年与交接](../../../chronicles/2026-11-24-isaac-performance-window-handoff.md)。

当前建议的快速实验配方是 **CPU PhysX＋天机原厂IK＋每100 ms动作5个物理子步＋两路相机各保持2个RTX渲染子帧＋有界后台记录**，已测完整规则采集周期约55.211 ms。每个动作仍返回头部与腕部各一张图像，双渲染子帧是在同一物理状态下为画面收敛做额外更新，不是增加相机数或额外物理推进。

**建议配方与代码默认值分开。** 裸worker默认500物理子步、DLS、CPU、双渲染子帧；批量研究入口默认20物理子步、DLS、CPU、双渲染子帧、同步记录。55 ms配方需要显式设置原厂SDK、5子步及异步记录，未全局切换默认值。GPU兼容模式与单渲染子帧同样为可选项，不能自动替代已验证合同。

### 从最早基线到当前配方

| 同一正常场景／种子91000 | 最早500子步＋原数值IK＋同步记录 | 当前5子步＋原厂IK＋异步记录，双渲染子帧 |
| --- | --- | --- |
| 完整周期量级，含记录 | 约770 ms | 约55 ms |
| 回合墙钟，不含Isaac启动 | 305.871 s | 19.933 s |
| 控制动作数 | 397 | 358 |

对外总结为单周期约快14倍、耗时减少约93%，正常回合从约5分钟降到20秒。原基线未直接记录teacher到teacher的周期，按正常样本排除最初10步与末步后，将teacher RPC、step RPC及spool append均值相加为768.364 ms；当前周期直接测得55.211 ms。另以整回合墙钟除动作数，两端分别770.456／55.678 ms，数量级一致。回合加速约15.35倍还包含动作数减少，不能与单周期加速混为一谈。

这是跨配方的整体加速，**并非全部来自同精度代码优化**：500→5子步把物理dt从0.2 ms改为20 ms，改变积分、目标插值与接触采样；原厂IK也替换了求解算法。当前5子步与20子步正常案例在相同控制序号的插入进度差最大约4.329 mm，最终深度均约51.281 mm。三种固定规则场景通过，不能外推为任意策略或真实接触精度认证。

## 早期阶段：四档物理子步与FK缓存

2026-11-24，用户询问仿真采集为何耗时，并要求比较每100 ms动作下5、20、100、500个物理子步。当时实现为CPU PhysX、逐子步同步推进；GPU主要负责RTX双相机。每个动作执行12轮数值IK，每轮需要1＋7次TCP正解；旧实现每次遍历38个body并重复构造固定变换。规则决策本身不是主要耗时来源，旧执行器存在明确重复计算。以下保留该阶段证据，当前结论以上方收口为准。

## 耗时归因与已实施优化

500子步下，物理循环约539 ms，IK约127 ms，渲染约40 ms，其余是测量、奖励势函数和通信。20子步下物理循环降到24 ms，未优化的IK仍约132 ms，成为主要部分。规则计算约0.94 ms；本机RTX 4090上真实BC网络的单样本双RGB十帧推理均值约7.9 ms（含输入传输与动作返回，100次测量、20次预热）。因此主要问题在执行路径，不是神经网络推理。

`Kinematics.tcp()`现在缓存固定body／site变换和关节轴，只计算TCP所属的9个节点，保留完整`frames()` API。该类要求传递包几何／关节定义在对象生命周期内不变，改变定义时重新构造。关节值q仍每次读取更新；未改变数值IK方程、迭代次数、动作限幅或任务判据。

验证包括200组非平凡旋转／滑移与原全树正解逐值一致、独立MuJoCo正解核对、无TCP站点及缓存不被返回值修改的回归。另用实际PhysX正常案例91000、20子步逐步对照：原／新均385步成功，全部关节目标和插入深度差为0。IK实跑降到约27 ms，worker总耗时约117 ms。该验证与单纯离线微基准分开；离线完整12轮IK约81→16 ms也单独保存。

worker新增显式`--physics-substeps 5|20|100|500`，与`--physics-dt`互斥；裸worker仍保留500子步的旧默认。新的`run_isaac_diverse_study.py`批量入口默认20，可显式传500恢复旧数值配置。每次实际dt写入执行合同，旧经验／检查点不能绕过合同核查静默混用。已采集的50段数据和它的BC验证仍使用原500子步，验证阶段只应用数值等价的FK缓存。
