## 原图、clip和resize

归档程序源码证明：`head_wrist_session.py`用`wrist_live --image-mode full`请求1920×1080 MJPG；`wrist_image.prepare_image(full)`不裁剪、不缩放、不去畸变；`capture_head_wrist.py`订阅`/omi/wrist/color/image_raw`，写原尺寸PNG并回读验证。

裁剪发生在人工预览／策略阶段：归一化ROI中心(.500,.704)、边长为短边.36，对1920原图得到`(766,566,389,389)`，右／下边界不含，即`[766:1155,566:955]`。人工预览用PIL Lanczos缩至128×128再显示放大；策略及ROI发布使用`rint(linspace(0,388,128))`采样。这两种插值不同，不能混用。

**正确顺序是：先在1920原图域用原始K/D检查几何投影，然后真实图、仿真图调用完全相同的ROI／resize。** 本轮不改焦距去凑截图，不从图2的边框反推相机。对比的拟合参考是已有unit001原始开发帧，不是128px截图。

原图K/D为：

```text
K = [[656.3888033, 0, 969.5144704],
     [0, 661.2072138, 551.7507394],
     [0, 0, 1]]
D = [-0.0272761885, -0.0038809502, -0.0024510944, 0.0027821863]
```

389 ROI的主点为(203.51447,−14.24926)，主点落在ROI上方不是K错误。人工128预览按像素中心对应时，等效`fx=215.98398, fy=217.56947, cx=66.63073, cy=−5.02418`；D不因clip／resize而改变。策略rounded-linspace的采样步长在3／4原像素间变化，一个缩放K不能精确代替全部光线，应使用实际128个索引。矩阵、索引、采集代码和哈希见[处理域追溯](/home/linux/Downloads/腕部相机_原图裁剪与内参映射_20261125.json)。

- 根部后侧外缘绝对Y为30.65 mm，接近黑体外缘30.646 mm；后侧根部宽18.95 mm。
- 先前统一加宽令7点误差由5.62增至6.48 px；最终保持后侧包络，正面根部宽在原图边缘约束下约15.93 mm，沿厚度平滑连接，避免把整个银壳等比例放大。

初次同域检查中，r15衬垫中位RGB约(252,250,30)、HSV色相30；图2橙色约(214,137,79)、色相13。颜色修订后约(210,135,78)、色相13。转为原图参考后，真实橙色中位约(225,145,84)，最终候选在同一ROI约(224,144,84)、色相13。只统计所示ROI，不将照片RGB当作物理反射率；MuJoCo像素拟合与Blender PBR近似分开保存，没有真实夹爪像素回贴。详情见[最终相机／像素报告](/home/linux/Downloads/夹爪相机_原图域最终核查_r16_20261125.json)。
