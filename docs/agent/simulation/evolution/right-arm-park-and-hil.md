# 右臂临时水平停放与Isaac人类反馈训练就绪性

后续用户明确接受规则接管作为反馈来源，已实际完成[规则反馈RL链路试验](isaac-rule-feedback-rl.md)：包括SAC、续训和独立评估；当前自主结果0/2。下文保留接入前的就绪性核对，真人输入与偏好评分接口仍未接入。

2026-11-22，用户要求右手水平伸展、避开腕部视线，并询问当前是否可做人类反馈强化学习。

## 右臂停放

在WG-r10＋OM-r08场景的独立副本中，将非操作右臂`Arm_R1_Joint`～`Arm_R7_Joint`设为0 rad，向身体右侧（世界−Y）水平伸展。肩部约(0,−0.2005,1.121) m，右TCP约(−0.00000146,−0.8965,1.120997) m；关节中心高度离差约3.06 µm，是模型数值结果。

只改变初始右臂关节姿态。XML及mesh几何不改，左TCP、光模块和腕部相机的FK位置/旋转与之前逐值一致。原资产和原场景保留；没有执行由旧姿态到新姿态的扫掠运动或真机命令。

Isaac重新渲染并使用右臂语义分割检查：全景中右臂36546像素，当前1920×1080腕部鱼眼图中0像素。右臂仍在场景里，没有隐藏或删除。该结论只适用于当前预插入姿态，不能扩展到任意后续相机运动。

首个校验要求六个腕部立方体面中必须看到右臂，未满足而拒绝；此要求不适合作为“移出视野后”的阳性对照。修正为在全景确认标签有效，再检查腕部鱼眼，失败稿保留。

## 人类反馈训练尚未就绪

当前Isaac新组合完成了资产装配、静态路径/投影检查和夹指展示；未完成新组合的动态插入/力门控、人工接管、经验池与learner闭环。右臂调整是场景配置修改，没有产生机器人策略学习更新。

实际代码核对：

- `omi_proj/src/omi_hil_rl/training/shapeforge_config.py`的transport仍要求`mujoco`，不是Isaac环境适配器。
- `contact_study_env.py`继承MuJoCo `ContactInsertionEnv`，合同只接受`policy/scripted_intervention`。此前10BC＋20RL中的接管来自规则老师，报告`human_actions=0`，不能作为真人反馈已完成的证据。
- `sim/keyboard_teleop.py`已有7维关节到达任务的人工输入/记录代码，但当前Isaac插接是6D TCP增量，接口与任务不同，尚未直接接入。
- `hil/actor.py`另有真实机器人human/demo路径；阅读它不等于可以对当前Isaac场景直接使用，更不授权启动硬件执行。

如果目标是**人工遥操作与接管纠偏**，下一步需要：新场景的动作/奖励/终止与接触验收；人工接管/释放及请求动作/实际动作/来源/时序记录；Isaac环境适配BC/SAC/replay，并完成采集、一次更新、重载和关闭接管评估。已有框架可复用，但当前链路尚未贯通。

如果目标是**对轨迹打分或表达偏好**，还需定义反馈如何变成奖励（或训练奖励模型）；当前也没有该接口。这里不将两种反馈方式混称为已实现。
