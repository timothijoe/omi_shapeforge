## MuJoCo 的碰撞表示

普通 mesh 碰撞使用凸形状，凹孔需分解；见 [MuJoCo 官方说明](https://mujoco.readthedocs.io/en/stable/computation/)。本轮建立独立局部夹具，将U形通道按源网格精确拆成底面与两侧壁；白色框架、模块槽面和折弯弹片使用 CoACD 分解，其余部件使用保守凸包。七片同形弹片使用平移模板。

分解缓存分别含白框221片、模块槽面14片、单弹片3片；这是近似碰撞表达，不是0.01 mm精度认证，CoACD的0.01为归一化阈值。真实三角面检查仍使用原始网格，分解后的局部接触结果另行比较。缓存缺失或源几何哈希不匹配时明确拒绝运行。

夹具保留所有外观和部件身份，模块由单轴伺服推进，力限2 N、重力关闭、质量20 g／摩擦0.2为假设。此场景隔离网格和接触问题，不含机器人抓取，不代表已验证真机插入力。

| 实际检查 | 结果 |
| --- | --- |
| 原部件直接按凸包碰撞 | 孔口外约0.79 mm被白框的错误凸包挡住 |
| 保留空腔、全部入口细件刚性 | 停在约4.212 mm；首次接触为模块下护片与孔口弹片 |
| 仅诊断主体通路，排除入口弹片组件碰撞 | 可到51.282 mm，由头部台阶／金属上口沿止挡 |
| 同一主体诊断横向偏移±1 mm | 均在孔口附近被挡住，不能穿墙进入 |
| 假设整个入口弹片组件由一个弹性铰链让位 | 仍停在约4.212 mm；假设未被接受为有效弹性模型 |

第一次铰链调试使用默认软限位，曾产生约11.75°超限，结果保留在 `compliant_trial/` 并判无效。加强限位后的 `compliant_limited/` 仅约0.00047°正向误差，依然不能通过，说明不是简单加一个弹簧参数就能完成这一组网格的插入。

## 原三角面和实体检查

重新执行0.25 mm路径采样并对首次相交二分，得到全刚体首次相交区间 **4.21094–4.21875 mm**；排除细接触部件的诊断终点为 **51.28125–51.28906 mm**。双向顶点／三角形中心包含检查没有发现更早的主体穿透。

主体诊断在深度25–50 mm的采样最小间隙约0.331 mm，位于模块下壳与推断的内部黑色件之间。采样距离是上估计，不能认证真实最小间隙；接近台阶后间隙自然降为零。

入口问题不止一组弹片：横向 `Spring retaining rolled seam` 位于 Z≈−1.7 mm，跨越通道宽度，会进入模块侧壁／内部简化块占用的空间。当前模型没有描述这条卷边怎样随着弹片让位。两者的自由形状、连接和运动应一起复核；单独删除内部简化块也不能消除与侧壁的相交。

## 接续工作

先依据空插座入口的正面／侧面结构复核七片弹片、横向卷边的连接和自由形状，再建立有明确变形范围的接触模型。需要检验弹片与底板／侧壁自身的接触，不能仅让弹片穿过底板以换取模块通过。照片能证明实物可插入，但不能单独认证当前隐藏细节和弹性参数。

当前应复用主体资产和已验证的孔形碰撞分解，继续修正入口接触组件，而不是从视觉策略调参入手。验收必须同时满足：保留必要接触、正常路径到台阶、偏心／倾斜会阻挡、无明显穿透，并检查步长敏感性。完整结果和源码快照由[清单](../../../../manifests/mesh_insertability_20261121.json)索引，命令见[教程](../../../../tutorials/mesh_insertability.md)。
