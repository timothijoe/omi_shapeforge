# 2026-11-21：实际 mesh 插入检查与阻挡定位

用户要求先保证模块正常插入，并检查 mesh 是否可用。本轮重新读取当前 V3／r04 Blender、导出150部件，原源文件哈希保持。结论为**完整模型未通过插入验收**，问题已经定位到碰撞体转换和入口细接触组件。

拓扑发现模块侧弹片共40个退化三角面和两条细折缝的开放端口；135件插接座网格均闭合。新碰撞派生副本清理退化面并封闭四个管口，保持包围尺寸，未覆盖 Blender 主资产。

对原三角面重跑0.25mm路径和二分，刚体首次相交为4.21094–4.21875mm；双向采样包含检查一致。U形通道和白框的单凸包封孔问题由实际MuJoCo测试复现：直接凸包在孔外约0.79mm阻挡。U形通道拆为精确三块、其他关键凹件分解后，阻挡移到真实弹片约4.212mm处。

只在诊断中排除入口22个组件碰撞，可推进到51.28171mm台阶，横向偏移±1mm则均在孔口附近阻挡。该通过只证明主体通路，不能作为完整插入结果。步长从0.2ms减至0.1ms时，主体终点和完整刚体卡点保持，最大数值接触侵入约0.008mm以内。

整体入口组件的单铰链弹性假设也做了试验。首轮软限位超限判为无效；加强限位的复验仍阻挡，未采纳为弹性解决方案。不能用这一假设、排除弹片或强制位移冒称正常插入。

运行目录 `/data/omi_runtime/runs/mesh_insertability_20261121/` 包含原始／修复导出、三角面与包含报告、凸分解、各MuJoCo场景和动态报告、结果图、源码快照。三项网格行为测试通过，控制环境14项通过、12项可选检查跳过。

能力现状见[网格可插入性](../evolution/mesh-insertability.md)，命令见[教程](../../../../tutorials/mesh_insertability.md)，精确哈希及测试见[清单](../../../../manifests/mesh_insertability_20261121.json)。后续优先复核入口弹片／卷边的真实连接和变形空间，再进行完整接触插入；本轮未训练RL或连接硬件。
