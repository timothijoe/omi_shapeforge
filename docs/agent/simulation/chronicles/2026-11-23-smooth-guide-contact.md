# 2026-11-22～23：入口受阻、内部顺滑的碰撞候选

用户澄清并确认：入口没对准可能被顶住，需要退回纠偏再插；正确进入以后内部光滑。因此先验证接触模型，而不是直接把旧BC／RL失败归因于策略能力。

本轮从固定WG-r10＋OM-r08／右臂停放的Isaac传递包派生独立候选。原视觉资产156个文件及原local／robot传递包的hash复核不变。用六个解析凸体表示连续通道、轴身和肩部止挡，替代旧零碎内部代理和未标定的0.15 mm行程触点；内部中心重新对齐名义18.8×8.8 mm通道。它是行为假设，未标定真实摩擦、弹片、锁扣或夹持。

开发中保留了多类失败和修正：

- 低力顶住不能只靠较高力阈值识别，增加接触与持续无推进的联合判断。
- 肩部可接触下沿或侧沿，r01只认上沿导致已经接触却不报到位；r02识别四条口沿，保留原位姿／力／穿透及连续三次末子步接触条件。
- 5 µm contact offset在局部循环可用，但机器人入口的瞬时穿透约0.0603 mm，减速仍未消除；这些回合全部判失败，后续恢复0.1 µm。
- 半物理步长下0.01 mm末段目标增量出现到位前停滞；后续有界控制使用最小0.05 mm轴向目标增量、0.1 mm到位目标余量，由实际止挡和原保护阈值限制物理运动。
- 初始化接触监视器时不应清空已建立的力字段；另加三项回归检查，覆盖首步前事件、四条口沿和历史末子步语义。

机器人恢复探针只在开头reset一次，之后全部经正常IK和PhysX驱动移动。末端瞬移专项只用于调试接触事件，不计入完整恢复结果；没有把旧策略回放或无图像脚本当作新BC／RL成绩。

控制环境46项检查中14项执行通过、32项因可选依赖／资源缺失跳过；新增三项接触监视器回归在具备NumPy／SciPy的环境执行通过。实际动态结果、复现和边界由[能力记录](../evolution/smooth-guide-contact.md)维护；所有过程目录保存在`/data/omi_runtime/runs/smooth_guide_20261122/`，各轮控制配方分别记录于对应的`protocol.json`，最终为`r06/protocol.json`。

最终有界试验为`r06/`：六个原生盒代理＋控制周期内目标过渡，局部5/5通过、机器人1/3通过。对准的半步长机器人完成到位和退出，内部287个控制样本无接触力；末端仍有13.67 N子步峰值。两侧偏移恢复在入口触发约0.056 mm的穿透保护，故整体未验收，未继续训练。原资产156份文件再次哈希确认未变，结果图已打开；正式登记见[清单](../../../../manifests/smooth_guide_contact_20261123.json)。r03及其余轮次均为保留的历史对照，不能覆盖最终未通过结论。
