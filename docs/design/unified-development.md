# 统一开发方案与工作拆分

整理日期：2026-11-20。依据 [HANDOFF](../../HANDOFF.md)、[当前总览](../current.md)、[能力总表](../capabilities.md)及现有 CLI、调度器、仿真脚本和测试。

本文是后续开发的建议基线。ENG-001 已完成，其余任务待实施；状态见第 7 节，不代表尚未开发的能力已经验收。最新能力事实仍由领域 `evolution/` 维护，本文只维护工作拆分、依赖和交付标准。

## 1. 要统一的工作

项目可以按五类工作组织。它们共享工程规则，但保留各自的算法、环境和验收方法；沿用现有感知、仿真两个知识领域，不新增空领域。

| 工作类别 | 已有基础，详见能力总表 | 后续工作 | 交付物与验收重点 |
| --- | --- | --- | --- |
| 感知与几何 | 官方双目样例、BundleSDF 组件、已确认 ROI 配准、冻结几何回放 | 真实双目样本接入、局部／完整重建、配准评估、59 帧尺寸重估 | 深度／点云／模型／变换矩阵；检查单位、坐标、有效区域和独立评估数据 |
| 模型与资产 | Blender 保存模型检查、15 部件导出 | 生成流程复现、尺寸校准、外观与碰撞体分离、资产版本管理 | 可追溯源模型、网格、资产清单；检查比例、原点、部件和碰撞结构 |
| 仿真场景 | MuJoCo 与 Isaac PhysX 单模块／2×2 原型 | 真实夹具、槽接触、机器人组合、跨引擎检查；GUI／RTX 单独验收 | MJCF／USD、场景清单、运行报告；检查装配、接触、运动及物理假设 |
| 机器人与数据接入 | 机器人资源恢复与离线预检、OMI 数据元信息 | 确定机械臂／夹爪配置，核对 TCP／关节；数据解码、动作语义、Actor 验证 | 机器人配置与坐标说明、数据验证报告；6 维末端增量不能直接当作关节／夹爪标签 |
| 工程基础 | 主 CLI、独立后端环境、运行记录、资源清单、4 项控制层测试 | 可恢复代码基线、统一任务与产物接口、自动检查、复现流程 | 确切代码版本、入口、配置、日志、报告；可在明确的环境和资源条件下重新运行 |

数据恢复已经完成，后续进入适配和验收。完整在线重建、精细插接、Actor 训练各自拆项，不因组件检查通过而提前标记完成。

## 2. 统一开发边界

沿用[仓库架构](project-architecture.md)：

- `omi_shapeforge`：任务入口、配置、进程调度、产物合同、配准评估、资产／场景生成和项目文档。
- `FoundationStereo`、`BundleSDF`：各自算法、原生扩展及环境适配；主项目引用确切版本。
- `omi_proj`：机器人资产、数据合同与相关实现的来源；跨仓库修改在所属仓库完成并记录依赖版本。
- `/data/omi_runtime` 等配置指定的外部路径：原始数据、权重、环境、生成资产、实验输出；Git 保存代码和小型元数据。

统一的是任务生命周期、数据边界、证据和开发流程。GPU 后端、Blender、MuJoCo 和 Isaac 继续通过各自环境运行。先为现有脚本增加适配层，再按实际复用需求抽取公共逻辑。

## 3. 当前工程缺口

| 已核实的现状 | 对开发的影响 | 建议处理 |
| --- | --- | --- |
| 原先后端适配未提交、本地仿真／文档未纳入 `dev` | 原 GitHub 默认分支不能恢复本机代码 | ENG-001 已保存本地提交、bundle 并整理本地 dev；远端待同步，见[源码基线](source-baseline.md) |
| 主 CLI 只有 `doctor`、两种 `smoke`；配准与仿真入口独立 | 同一项目的参数、路径和运行方式不一致 | 逐项接入共用运行层，保留可独立调试的后端入口 |
| 主调度器检查后端报告的状态字段，未做完整结构校验 | 缺字段、单位或产物不匹配可能未被发现 | 增加带版本的数据合同与产物校验，分别定义运行成功和验收通过 |
| 仿真报告与主运行清单结构不同，部分旧报告来源字段较少 | 各流程证据无法直接合并判断 | 对新运行提供统一外层记录，保留各后端原始报告和旧证据 |
| 当前只有控制层测试，仓库尚无 `.github` 工作流目录 | 后续入口增加时缺少自动回归门槛 | 建立 CPU 自动检查；GPU／仿真按变更范围运行并保存证据 |
| 相机配准与合成场景尚未对齐；机器人配置及动作语义待核对 | 各组件独立通过，仍不能串成可信任务 | 显式定义坐标链、机器人配置和动作转换，校验通过后再集成 |

## 4. 每个任务的共同合同

下列是拟新增的约定，当前脚本尚未统一实现；字段名在实现前与[现有格式](../agent/interfaces/data-formats.md)核对并定版。

| 内容 | 最小要求 |
| --- | --- |
| 任务说明 | 明确输入、输出、范围、依赖、验收指标、未覆盖范围；指定一个主责仓库和关联仓库 |
| 输入身份 | 资源标识、来源、版本／哈希、样本选择及标定文件；路径来自配置或显式参数 |
| 代码与环境 | 主仓库和后端版本、工作树状态、解释器、关键依赖版本；本地探索可记录脏工作树，正式复现必须能恢复实际源码 |
| 运行身份 | 唯一运行标识、任务类型、解析后的参数、完整命令、起止时间和新输出目录 |
| 运行结果 | 退出码、异常／中断原因、日志路径、产物列表及哈希；失败也保留记录 |
| 验收结果 | 独立记录通过／失败／未评估、检查方法、阈值、观测值和证据；缺少必需报告或产物时不能通过 |
| 几何语义 | 长度单位、坐标系、轴方向、变换方向、相机标定／尺度来源；明确几何是否已应用变换 |
| 物理与动作语义 | 质量／摩擦／惯量等假设；关节名称、顺序、单位、限位、TCP；动作是关节量还是末端增量 |
| 格式演进 | 新合同具有版本；保留后端原始报告，通过适配读取历史产物，不回写旧报告来满足新格式 |

“进程正常退出”“产物有效”“任务达标”分别判断。比如点云成功导出不证明尺度准确，配准残差低不证明真实位姿准确，场景落台稳定不证明可以插接。

## 5. 实施顺序与验收门槛

| 阶段 | 工作包 | 完成标准 | 依赖 |
| --- | --- | --- | --- |
| M0 可恢复基线 | 清点各仓库变更；保存后端适配与入口；整理本地仿真／文档与 `dev` 的关系；记录资源和环境来源 | 能从记录的源码版本重建代码工作区，无遗漏的未跟踪运行入口；控制层测试和相关已有 smoke 有与版本对应的证据 | 现有工作树与交接资料 |
| M1 共用运行层 | 定义任务／产物合同；抽取通用进程运行、日志、失败处理与报告校验；先迁移现有 smoke，再接一个仿真入口；加入 CPU 自动检查 | 同一运行约定覆盖这两类任务；缺产物、坏报告、进程失败和输出目录冲突均正确处理；对应实际流程通过 | M0 |
| M2 真实样本闭环 | 固定一个真实双目样本及标定，运行深度／点云、已确认目标配准和评估；显式保留人工 ROI／方向先验 | 从原始输入重新计算，产物来源和坐标链完整；有独立评估记录及事先确定的阈值，无法测量的实物精度明确标记未评估 | M1、样本／标定核实 |
| M3 机器人场景闭环 | 选定一套机械臂／夹爪／TCP；接入光模块与真实夹具；建立能表达槽接触的碰撞体；先 MuJoCo，再按相同场景规范检查 Isaac | 关节映射、尺度、TCP 和限位有检查证据；完成指定运动／接触场景并记录结果与模型假设 | M1、机器人配置与夹具核实；用感知结果驱动时还依赖 M2 |
| M4 专项扩展 | 完整视频在线重建、59 帧尺寸、完整 Blender 生成、GUI／RTX、OMI 数据／Actor 与训练分别立项 | 每项独立输入、指标、资源预算和报告；训练须先明确动作合同与独立评估划分 | 按专项依赖 M2 或 M3；数据审查可提前开展 |

优先推进 M0 → M1 → M2。M3 在配置核实后可以独立推进；暂不把所有专项塞入第一轮开发。阶段按验收推进，工期应在样本、配置和计算成本核实后再估计。

## 6. 日常开发流程

1. **任务建档**：在任务说明或 PR 中填写下面的模板，先定义完成标准。性能／精度阈值必须在正式评估前确定。
2. **检查基线**：查看工作树和依赖版本，保护已有未提交内容。保持 `main` 为空；M0 整理开发基线后，后续功能从 `dev` 建分支；跨仓库变更分别记录。
3. **小步实现**：一项任务形成可审查的变更；算法修改留在后端，任务调度留在主项目，避免复制整份旧工程。
4. **按影响验证**：控制层执行 `.venv/bin/python -m unittest discover -s tests -v`；后端调用变更执行相关 smoke；几何／仿真变更验证相应产物和实际工作流。文档修改检查链接和事实。
5. **复核交付**：提交范围清晰，说明行为变化、验证结果、依赖版本和剩余限制；CI 无 GPU 时只声明完成 CPU 检查，GPU／仿真报告另行关联。
6. **更新知识库**：先更新能力 `evolution` 与接口／教程，再更新 `current`；有已验证阶段时追加 `chronicles`。计划完成不能直接变成能力验收通过。

最小任务模板：

```text
任务标识与标题：
目标／本次范围：
主责仓库／关联仓库：
依赖任务／代码与资源版本：
输入／输出／坐标与单位或动作语义：
验收方法／指标／阈值：
验证环境／预计计算与存储开销：
执行命令／输出目录／报告位置：
结果／未覆盖项：
需同步的接口、教程与能力文档：
```

任务状态建议使用“待开始／进行中／待验证／完成／受阻”；受阻时写出缺失条件和下一步。只有交付物、相关检查和文档都齐全，任务才标记完成。
