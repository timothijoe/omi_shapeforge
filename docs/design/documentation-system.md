# 文档体系与维护规则

## 本轮项目参数

项目为当前仓库 `omi_shapeforge`，领域为 perception 和 simulation。交接资料来自迁移包 HANDOFF、光模块便携包说明及已有验证 JSON；参考项目为同级 FoundationStereo、BundleSDF 和仅作资产资料来源的 omi_proj。大资源根目录由工作区配置指定，本机为 `/data/omi_runtime`；环境与暂缓范围见资源清单及当前总览。

本轮范围是中文文档、资源元数据和忽略规则。保留既有实现、历史证据及用户提供的 PROMPTS 原文，不连接硬件，也不执行推送。

## 权威来源

代码、CLI help、工作树和可核验报告共同决定事实。`docs/current.md` 是全项目唯一当前摘要；领域 `current.md` 只摘要本领域；能力 `evolution/*.md` 维护该项能力最新、完整的事实。表格和教程引用这些事实，不各自形成另一套进展结论。

| 载体 | 职责 | 更新方式 |
| --- | --- | --- |
| README／各级索引 | 最短入口与导航 | 随链接变化更新 |
| charter | 目标、职责、依赖方向和完成标准 | 稳定维护，链接能力纪传体 |
| current | 当前摘要与能力索引 | 随已确认状态变化更新 |
| evolution | 架构、数据流、入口、约束、证据、限制 | 可重写并清理失效事实 |
| chronicles | 已发生且有证据的阶段 | 永久追加；错误另写勘误并反向链接 |
| decisions | 长期架构决定 | 递增编号；替代时标记 superseded |
| interfaces | API／CLI、格式、资源和边界 | 与实现同步 |
| tutorials | 面向操作者的前提、命令、预期和排错 | 保持可执行，不堆开发历史 |
| manifests | 小型资源元数据与证据索引 | 明确检查日期，保留冻结验证记录 |

本项目只有感知和仿真两个已形成真实能力的领域；尚无真机、遥操作或生产领域，暂不创建对应空结构。

## 维护流程

开发前读领域 charter/current/evolution 与工作树。完成后先更新能力事实及证据，再更新摘要、教程和索引；有已验证阶段时追加编年。普通参数修改不单独编写长期决定。

历史记录补录须注明补录日期和依据，不能把旧机记录写成本机验收。旧入口保留导航，避免外部链接失效。原始聊天、临时推测和无结论日志不进入知识库。

本轮整理未修改算法与调度实现，未删除历史资产或旧文档文件；原有三篇入口按上述职责重组，之前内容仍可由 Git 历史追溯。验证方法与结果见[文档检查记录](../../manifests/documentation_validation.json)。
