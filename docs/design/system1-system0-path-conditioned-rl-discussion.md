## 当前实现承担的职责

ShapeForge 的 Isaac 学习实验目前采用双 RGB 十帧历史与有效性掩码，经 ResNet-10 当前帧和历史分支、128维融合特征，再由 SAC Actor 输出归一化六维动作。Actor 和双 Critic 使用同一观测编码体系。当前 Isaac 观测中的 state 和 tactile 是零填充，仿真真值供规则、奖励和评估使用。

动作经尺度转换生成 TCP 位置与朝向目标，再经过 DLS 或天机 IK、关节位置伺服，由 PhysX 推进。控制周期为100 ms。后三个动作以旋转向量增量组合旋转，不是三个欧拉角的直接相加。

因此，当前策略是未显式分层的局部视觉动作策略：空间判断、对准、推进与恢复同时压在同一个策略上。按执行位置它接近 System0，按本次“处理真实接触”的定义又尚缺有效的接触观测。规则接管是替换策略动作，不是上层给子目标、下层独立执行的层级架构。

当前六维增量也不是 residual。它表示从当前位姿出发的完整运动命令；residual 则表示相对某个基础策略或控制器动作的修正。

项目已有单独的腕部感知网络：共享 ResNet-18、双目标注意力与局部裁剪、模块与插座位姿头。它是 System1 的基础组件，但没有作为显式位姿接口接入当前 RL 控制链路。

实现核对入口：

- [Isaac worker](../../scripts/simulation/isaac_rl_worker.py)：观测、奖励和 teacher 通道。
- [Isaac 执行环境](../../src/omi_shapeforge/sim/isaac_contact_runtime.py)：六维动作、IK和100 ms控制步。
- [腕部双目标网络](../../scripts/perception/image_to_surface_network.py)：图像到位姿及模板表面。
- [共用 SAC 网络](../../../omi_proj/src/omi_hil_rl/hil/networks.py)与[Isaac 训练编排](../../../omi_proj/src/omi_hil_rl/training/isaac_rule_feedback.py)。
- [现有规则恢复](../agent/simulation/evolution/online-insertion-recovery.md)与[50段示范结果](../agent/simulation/evolution/diverse-demonstrations.md)。规则通过与学习策略自主成功分别计量。

## 为什么用路径分工

空间几何可以在限定范围内大量采样，而摩擦、刚度、夹持松紧和触觉响应存在实仿差异。路径把大部分运动方向和动作顺序显式交给上层，让下层集中处理局部执行。

System0 的任务范围可以很窄，但对该范围内接触变化的适应要求仍然很高。分层没有消除接触迁移难点，而是试图把适配集中到较小的局部问题。

同类插接优先在插座局部坐标系中表达。孔位变化主要由坐标变换处理，下层输入则表达“相对路径横偏多少、姿态差多少、接触如何变化”。这有机会减少为不同世界位置重复学习相同行为。机械臂构型、重力方向、可达性及不同接触机制仍需覆盖，不能据此宣称任意位置或任意技能泛化。

现有[细网格数据](../agent/perception/evolution/grid-perception-data-v1.md)是有边界的分层覆盖，并非全部变量的完整笛卡尔积；图像是孔口前独立静态视图，不能直接当时序路径监督。[接触版感知评估](../agent/perception/evolution/contact-wrist-surface-learning.md)的尖端相对孔口均值约0.982 mm，最差约10.974 mm，尚不能作为精密入口对准已成立的依据。

## 路径表征与获得方式

给执行层的是三维位姿路径，每个路点同时包含位置和朝向。二维图像线条可以作为上层提示，但必须借助深度、标定、已知物体模型或其他几何信息转换成三维，单张图上的像素线条不能唯一确定深度和姿态。

用进度 s 参数化参考位姿 T_ref(s)，附加阶段、名义速度、速度上限和允许偏差。它是带速度配置的路径，实际时间参数化由执行反馈调整，不要求第几秒必须到哪个点。

对当前光模块任务，先用 mesh 定义尖端、孔口、插入轴及名义到位关系；根据当前相对位姿生成接近、孔外对准、轴向插入与恢复路径。少量位姿路点经位置和旋转插值形成连续路径，成功规则轨迹提供实际达到的位姿与参考验证。路径生成还要检查可达性和碰撞，不能仅因为插值平滑就认为可执行。

任务路径优先表达模块尖端的运动，再根据当前夹持变换转换为 TCP 路径。若模块发生滑移，应更新夹持关系；TCP运动学本身不能证明尖端仍在名义位置。

阶段判断与到位判断使用实际反馈。参考进度不能只按已发送的动作或经过的时间递增，也不能仅凭几何最近点跳过入口资格。局部让位范围按任务几何确定，受阻恢复与正常推进采用明确阶段。

## Horizon 与上下层遵从关系

| 范围 | 首版讨论配置 |
| --- | --- |
| 上层规划 | 保留整项任务的阶段结构，提供当前阶段完整路径与下一阶段入口 |
| 下层输入预览 | 约8个位姿点，名义速度下约0.5～1秒的行进距离；孔口及接触转换处加密，保留阶段标记 |
| 下层动作 | 每100 ms输出并执行一次六维命令，再读取反馈 |

预览长度不是 SAC 内部模型预测优化的 horizon，也不是连续开环执行时长。可比较4／8／16点，并分别统计接近、入口和内部推进的表现。

目标物体、目标插槽、禁入区域及阶段前置条件构成任务边界。路径中心线和名义速度允许调整：System0 可以在规定范围内让位、减速、暂停；持续受阻则按允许的恢复动作退回或请求上层重规划。上层提出的条件必须落入已验证能力范围，不能靠语义指令让下层获得新接触技能。

约束需要相应执行检查，不应只依赖奖励惩罚。真实接触峰值也不能仅靠100 ms策略周期保证，需要结合底层控制和保护能力。

## System1 网络候选

近期采用显式几何状态与小型规划头，保留未来 VLM／WAM 的接入位置。

1. 复用双目标 ResNet-18 感知，得到模块和插座位姿，计算尖端相对孔口关系。有效性与不确定性需独立验证，现有 presence 输出不能直接当作已标定置信度。
2. 拼接相对位姿、夹持关系、实际运动状态、阶段及技能／约束编码。首版规划头可用两层256维 MLP；若确有遮挡历史需求，再考虑 GRU。
3. 输出阶段提议、路径模板与少数中间控制点修正、名义速度配置。几何解码器固定任务端点和插入轴等关系，生成路径并检查可行性，再采样给下层。

感知使用位姿标注监督；规划头使用规则路径或示范监督，并加入接近真实分布的感知误差。暂不把 System1 定为必须由 RL 训练。后续若出现多种明显不同的路径，可比较 Transformer 或 Diffusion 等序列生成方案。

VLM 可以选择技能、对象、阶段和语义约束；WAM 在本讨论中按 World Action Model 理解，可以提供候选路径或动作片段。两者均应转换到同一结构化接口，再经几何与能力检查。

“保持朝向”需要绑定坐标系和允许偏差；“轻轻插入”需要映射到经实测的速度与接触配置。模型生成的未来画面不能替代真实接触与到位反馈。

## System0 直接动作与 residual 的比较

本轮讨论先提出基础跟踪器加 residual，随后澄清：路径条件不要求独立跟踪器，residual 只是动作参数化选择。当前倾向先做路径条件化 SAC 直接输出完整六维增量。

| 方案 | 计算方式 | 适用的验证问题 |
| --- | --- | --- |
| 路径条件化直接动作 | 路径预览、阶段、实际运动和触觉输入 SAC，输出完整六维动作 | 增加显式路径条件是否已经足以降低学习难度 |
| 基础跟踪器加 residual | 基础动作与 RL 受限修正组合，可另调推进速度 | 基本运动是否占用过多学习预算，接触残差能否更有效适配 |

直接动作方案中，主任务仍是成功插入；路径提供方向、阶段和可调整范围。无接触时沿参考接近，接触时允许局部让位，持续受阻时暂停或恢复。追踪和插入可以由同一策略共同完成。

residual 方案需要明确基础动作来源、修正坐标与幅度、组合顺序和推进速度控制。若加入速度系数，动作维度、Critic、经验池及合同同步更新。以 residual 为动作定义时，Actor、Critic与replay必须一致；最终执行的完整命令单独记录。旧完整动作标签不能不经转换就当 residual 标签。

现有 SAC、示范、接管和经验管理可作为工程基础；路径条件、接触观测和网络输入改变后，需要新合同与重新训练，不能将旧检查点直接视为已具备这些能力。

## 异步通信与位姿误差

真机候选采用 ROS 2 双向 topic；System0 内部网络与动作处理可用同进程调用。训练侧现有 Unix socket 不必因新设计立即改成 ROS，优先统一数据语义。

| 方向 | 拟新增话题 | 主要内容 |
| --- | --- | --- |
| System1 到 System0 | `/omi/system1/reference` | task／plan／revision、观测时间、坐标系及参考时刻、有效期、路径、阶段、速度、允许偏差、接触与恢复配置 |
| System0 到 System1 | `/omi/system0/status` | 接受的计划版本、实际进度、阶段、误差、运行／受阻／完成／请求重规划及原因 |
| System0 到执行器 | 沿用 `/omi/action/decision` | 经既有坐标、单位转换与仲裁的最终动作；保持单一自动动作出口 |

路径消息拟采用有类型的自定义结构，上述话题和字段尚未实现。下层缓存最后一个有效计划，持续读取最新实际状态执行；新计划到达时检查版本、时效、当前状态可接续性，再原子替换。计划过期或不可执行时按约定暂停与反馈。

在同一基座坐标系中，位置误差可由 TCP参考位置减去实际TCP位置得到；旋转使用相对旋转。计算这种参考误差不等于引入基础路径跟踪器，误差也可以直接作为 RL 输入。

腕部图像必须用采集时刻的相机／机器人变换落到基座或任务坐标系，不能用推理结束时已移动的相机姿态。机器人实际反馈不能由上一条命令代替。replay保存每次观测实际使用的路径版本、进度与时效信息，不能训练时用最新计划重算旧输入。

训练应覆盖上层延迟、抖动、旧计划保持、路径误差及更新切换。异步不要求忽略时间一致性。

## 仿真与真机奖励

路径作为观测条件与路径作为稠密奖励是两个独立选择。Isaac 当前已经用目标距离、姿态误差的势函数，结合成功／失败和每步代价计算奖励；增加路径观测并不要求再增加贴线奖励。

先保留同一任务奖励，比较有无路径条件的策略，可分辨改善是否来自观测。若仍难学习，再比较较弱的进展或越出允许范围惩罚，避免原地贴线得分、顶着接触追进度、路径更新产生虚假进展，以及过度惩罚必要退回。

部署推理无需真机逐步计算稠密 reward，但仍需完成、受阻等反馈。仿真可用真值训练奖励，同时给策略输入经测量建模的观测噪声、延迟和夹持变化；这与策略仅接收可部署观测不矛盾。

真机继续在线训练时，奖励应依赖可信信号。现有 `RealHILEnv` 以操作成功事件生成 `float(success)` 稀疏奖励，并非视觉距离奖励。可先使用可信成功／失败、示范和接管数据，后续再独立验证自动成功判别器。

TCP追踪准确只说明机器人跟踪参考，不证明孔口估计正确、夹持未滑移或插入已完成。同一个有偏估计器同时生成路径和评价追踪，可能给出好分却没有完成物理任务。最终结果需要适合任务的独立实测、经验证的分类器或人工标签。

若实际每步进展小于位姿估计抖动，帧间距离变化的正负可能不可信。先测误差、偏差、遮挡跳变和时延，再决定进展奖励的尺度与统计窗口。势函数塑形的理论条件也不能自动推广为“带噪估计和异步更新下任意奖励都保持目标不变”。

## 下次讨论与实验顺序

下一次优先确定以下问题，再决定是否实施：

1. 路径以模块尖端还是TCP为正式参考，插座坐标、夹持变换与动作坐标如何定义。
2. 第一版使用几何路径还是训练小型路径头；如何从现有规则轨迹提取监督，如何补足连续运动与遮挡覆盖。
3. System0 的最小可部署观测：哪些实际位姿、速度、双指触觉或力信号已经可靠，时钟和单位如何对齐。
4. 确认直接动作作为首个基线，以及 residual 对照采用何种基础控制器。
5. 路径消息的进度、约束、有效期和恢复语义，以及计划替换和受阻后的动作权限。
6. 真机在线训练的成功标签来源，位姿奖励可接受的误差尺度，感知不确定时如何处理。

实验按依赖逐步开展：先用已知几何产生路径，验证路径条件化直接动作；再加入实际估计误差和异步延迟；测清可处理的局部偏差与接触变化；必要时比较 residual；最后接入学习感知及 VLM／WAM。固定留出初态，分别统计成功、接管、恢复、接触负载与失败原因，不能将规则真值通过或展示视频当作新策略成绩。

## 相关研究

- [Residual Learning from Demonstration](https://arxiv.org/abs/2008.07682)：运动基元与任务空间残差学习，包含插接任务与真实机器人验证。
- [IndustReal](https://arxiv.org/abs/2305.17110)：接触装配的仿真训练与真实部署，证明特定设置的迁移可行，不代表本项目已完成迁移。
- [VoxPoser](https://voxposer.github.io/)：语言与视觉约束落到三维空间并用于规划。
- [Diffusion Policy](https://diffusion-policy.cs.columbia.edu/)：条件动作序列生成与滚动执行，供未来多路径方案参考。
- [HIL-SERL](https://hil-serl.github.io/)：真实机器人在线RL及成功奖励分类器的实践。
- [Policy invariance under reward transformations](https://people.eecs.berkeley.edu/~pabbeel/cs287-fa09/readings/NgHaradaRussell-shaping-ICML1999.pdf)：势函数奖励塑形的理论条件。
