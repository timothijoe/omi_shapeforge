## 资产为什么显示为一个

目前交付的是一套装配资产包 `SIM-OM001-OS001-r03`，相对原V3／r04独立保存。包内的模块和插接座是两个独立MuJoCo body，弹性触点是插接座下的7个独立body，并未合并成单一mesh。

| 组成 | 外观／接触对象 |
| --- | --- |
| `sim_module` 光模块 | 15个外观件、28个凸碰撞件 |
| `sim_socket` 插接座／支架 | 113个保留外观件、335个凸碰撞件 |
| `compliant_pad_0..6` | 7个等效弹性触点，各有被动滑动关节 |
| 文件组织 | 一份装配Blender、一份局部MJCF、491份OBJ和清单；Blender共501对象，包含相机／灯光 |

当前没有分别交付“模块专用blend”和“插接座专用blend”，也未分别登记两个可独立加载的子资产条目。这是资产封装尚未细分，不能把“一套包”解释为只有一个物体。r01／r02是保留的旧候选，只有r03作为当前通过版本；三个修订也不等于三个不同物体。原V3／r04及150份既有输入mesh哈希保持。

## 已完成的工程链路

ShapeForge真实URDF／新接触资产／双相机 → 十帧观测 → OMI Actor → 接受的6D命令与实际运动 → 单帧录制／replay → BC／SAC → checkpoint／权重回用／续训已执行。

截至原短试跑：400次BC、22次Critic更新（含8次预热）、7次Actor更新；4个在线回合1176条经验，环形池保留1024条。规则数据10回合实际只有6回合1046条用于训练，其余2回合验证、2回合测试。没有在线接管，规则数据只是离线混入训练。

## 当前问题与新实验范围

1. 原V3／r04的完整刚体几何仍在约4.212mm被入口组件挡住。新等效资产的通过不代表原件已被真实标定。
2. 新视觉策略能推进到51mm附近，但旋转误差积累到约0.063rad并卡滞，超出0.01rad要求。示范覆盖、观测可辨识性和控制形式尚未做充分归因，不能直接断言“视觉算法本身有问题”。
3. 新任务已使用pre-tanh BC处理饱和梯度；旧Z轴饱和模式改善，但低动作MSE不是闭环成功证据。
4. 原仿真奖励为逐步负位置误差，成功轨迹在γ=0.98下折扣回报约−20.5，失败惩罚仅−1，且缺少连续姿态反馈，需要审查其是否鼓励提前失败。
5. 既有22次更新只是接口冒烟。原OMI配置有1000次Critic预热、按在线样本数计算更新额度；不能把它与10回合BC＋20回合带干预RL直接比较。
6. 尚未分别封装模块／插座子资产，参数和相机／工具需实物标定；模拟卡滞力较大，还需合适的力限和恢复逻辑。

本次后续实验将固定mesh／碰撞／成功条件，单独比较BC旋转加权、修正奖励及在线规则接管。计划10回合用于BC训练，验证／测试另留；运行20个带接管的RL回合，记录请求动作、实际采用动作、接管来源和占比，最终关闭接管评估。旧实验和原资产不覆盖；新结果待实际运行后另记，不能预先保证20回合必然成功。
