## 当前分工与设计方向

| 项目 | 当前方向与实施状态 |
| --- | --- |
| System1职责 | 提供平滑接近入口的空间参考、插入轴和目标；未来可接VLM／WAM及语义约束 |
| System0职责 | 接收参考、实际运动及腕力，直接输出完整六维TCP增量；推进、暂停、倒退和局部重试由下层决定 |
| residual | 保留为未来对照，目前使用直接动作SAC，不要求独立基础路径跟踪器 |
| 输入传感器 | 暂不做双指触觉，先使用腕部六维力／力矩；已实现的是理想补偿后的仿真外部接触wrench |
| path还是轨迹 | 推荐三维位姿path加名义速度／速度上限，由System0决定实际时间进度；速度配置仍需正式接口实现，不能把建议当已部署能力 |
| 局部预览 | 原型8个位姿点、0.5 mm点距，每5个100 ms周期更新；点数、长度、采样和短路径mask待进一步确定 |
| 异步 | 已用仿真步实现上层更新／延迟队列；ROS topic、真实并发通信与部署保护未接入 |
| 老师来源 | GT几何与专家路径分开；规则定义入口与朝向约束，局部解析路径先行，规划算法扩充自由空间／避障；人类接触恢复示范主要用于System0 |
| 真机奖励 | 推理不需要逐步reward；在线训练优先可信任务结果，位姿噪声下的稠密进展奖励需单独验证 |

当前System1网络输出的是插座相对TCP位姿，参考路径由固定几何程序解码。尚未实现网络直接输出自由路径控制点，也未接入新的运动规划算法。可视化里的预测路径遵循同一解码规则，不能解释为机器人已经执行或完成插入。

三维path的每点应包含位置与朝向，图中的线展示位置。发送绝对参考或相对当前TCP的位姿序列时，应明确坐标与时间；不能把各个参考点误作连续位移增量累加。相机估计需要使用采集时刻变换，模块滑移时还要更新夹持关系。

## 已完成的实现与检查

学习侧新增独立包 `omi_proj/src/omi_hil_rl/training/hierarchical_insertion/`，包括GT／噪声／视觉System1、路径与状态包装、BC＋SAC、模型与经验池续训、无teacher评估及System1监督训练。ShapeForge新增独立launcher、腕力观测器和可视化／九位置探针。

旧RL网络、经验池实现及默认训练入口保留。worker新增的腕力选项默认关闭；同样两组初态下，开关观测器各规则2/2通过，720步动作、TCP、关节、深度和奖励项逐值差为0。

腕力以模块受到的外界接触冲量矢量合成，并计算相对传感器原点的力矩，按100 ms区间平均。虚拟传感器轴向随TCP，默认原点为TCP，可配置安装偏移。它不包含真实传感器零漂、噪声、惯性、重力载荷或工具其他部位接触；当前固定夹持原型没有验证滑移。

轻量测试95项：29通过、66跳过；训练环境同套检查67通过、28跳过。既有训练相关回归52通过、1跳过；新层级测试11项通过，覆盖坐标、延迟、真值隔离、倒退、检查点与种子。续训初次发现SB3重复旧种子，已修正并独立重跑，旧目录保留。

## 下一步讨论与实施起点

用户已把当前优先级放到System1，接续先处理九位置暴露的接近范围覆盖不足，不能只继续在原两条正常轨迹上增加训练轮数。

1. 讨论System1的实际工作范围：入口前距离、左右／上下偏移、姿态、孔位与夹持关系变化；先确定边界和独立测试划分，再扩充数据。九个诊断位置如果用于调参，应另建新的盲测集。
2. 确定老师：规则给阶段与约束；简单局部通路可解析生成并检查，复杂接近采用规划器。接触试探与倒退动作作为System0技能数据。多条可行路线需要一致的选路原则或明确的多模态监督。
3. 确定对外动作空间：短段位姿序列还是少数控制点，点距／有效长度／mask、朝向表示、速度配置和参考突变处理。目前8点是起点，不是已验证最佳horizon。
4. 先训练并可视化System1，检查不同起点、尾部误差、遮挡与路径有效性；当前CNN可作基线，是否接已有ResNet-18需另外比较。
5. 再固定参考生成器训练可靠System0，补受阻—倒退—调整—重插示范，独立评估GT和噪声条件；最后固定两个模块组合评估。

本次归档不启动新训练、不改变上述实验结果。现有并行感知数据小试、r16资产与其他工作有独立文档，不混为本System1训练的数据或验证结论。
